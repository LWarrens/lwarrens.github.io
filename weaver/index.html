Architectural memory for coding agents

Your codebase remembers.
Now you can ask it.

weaver turns symbols, Git history, and ADRs into evidence-backed facts. Catch constraint violations before they merge. Trace a symbol's full decision history. Detect accepted decisions that no longer match reality.

Get started → Browse the tools
MIT / Apache-2.0· Rust· SQLite bitemporal· optional embeddings· Streamable HTTP + stdio
📄
Code shows
What exists
Functions, structs, modules — current state, stripped of intention.
📜
Git shows
What changed
Commits and diffs — the chronology, without the reasoning behind each decision.
🗂
ADRs show
Why decisions were made
Prose documents that drift from reality and are almost never consulted before a change.

weaver enforces alignment across all three: a living bitemporal source of truth. Voids in the record are filled with tagged synthetic data, so even when evidence isn't present, relations stay discoverable.

Quickstart
1
Build and run the daemon
Requires Rust toolchain. No DATABASE_URL needed — the database is created automatically on first run.
shell
cargo build --release
# Persistent Streamable HTTP daemon (recommended)
./target/release/weaver \
  --db ./memory.db --daemon --bind 127.0.0.1:8444
# MCP endpoint: http://127.0.0.1:8444/mcp
# Preserve the mcp-session-id header from initialize
2
Connect your MCP client
Works with VS Code Copilot, Claude Desktop, and any Streamable HTTP client. Stdio is also available for clients that don't support HTTP.
mcp config
{
	"mcpServers": {
		"weaver": {
			"url": "http://127.0.0.1:8444/mcp"
		}
	}
}
3
Ingest your repository
Run these three calls once. After that, sync_incremental resolves what changed since the last index automatically — no need to re-run all three.
initial ingest
# 1. Parse ADRs → decisions, constraints, supersession links
architecture.sync_adrs_from_git
	{ "repo_path": "/your/repo", "adr_glob": "docs/adr/*.md" }

# 2. Extract symbols + call graph + community detection
#    Content-hash skipping keeps subsequent runs fast
architecture.ingest_symbols
	{ "repo_path": "/your/repo" }

# 3. Walk git history → commit ↔ decision links
architecture.sync_commits_from_git
	{ "repo_path": "/your/repo" }

# Subsequent runs — resolves changes automatically
architecture.sync_incremental
	{ "repo_path": "/your/repo" }
Tools

Tools across four categories. All return strict JSON. Every result is traceable to a source artifact.

architecture.sync_adrs_from_git
Parses ADR markdown, upserts decisions and constraints, resolves supersession links. The entry point for architectural memory. Idempotent — unchanged ADRs are skipped.
ingest
architecture.ingest_symbols
Walks source files via tree-sitter with content-hash skipping. Extracts symbol spans and enriched metadata (signature, cyclomatic complexity, visibility, decorators). Automatically runs containment edges, HTTP route detection (Express, FastAPI, Flask, Actix-web), and label-propagation community detection.
ingest
architecture.sync_commits_from_git
Ingests git history and creates decision↔commit links. ADR IDs in commit messages score 0.95 confidence; keyword overlap scores 0.6. Embeds commit messages at ingest time if a provider is configured. Idempotent.
ingest
architecture.sync_incremental
Resolves what changed since the last index (or a given git ref / ISO-8601 timestamp) and re-syncs only affected ADRs and source files. Use this for scheduled or CI-triggered updates after the initial ingest.
ingest
architecture.record_decision_episode
Stores architectural events from PR comments, meeting notes, or Slack threads. Embeds content at ingest time. LLM-extracted facts are marked with their confidence. Discussion is never silently promoted to accepted decision.
ingest
architecture.embed_all
Backfills vector embeddings for all decisions, constraints, episodes, commits, and symbols that don't yet have one. Idempotent — only unembedded entities are processed. Run once after enabling a provider on an existing repo.
ingest
architecture.query
Hybrid search via Reciprocal Rank Fusion across keyword (LIKE match on decision text and ADR titles), semantic (cosine over stored embeddings, threshold 0.30), and graph (BFS on temporal_edges, depth capped at 2) strategies. Degrades gracefully to keyword-only without embeddings.
query
architecture.find_decisions_for_code
Resolves a file or symbol to its active decisions and constraints. Appends HTTP route info when the file contains route definitions. Includes superseded decisions when historically relevant. Module/service resolution returns a warning (not yet implemented).
query
architecture.index_status
Reports the current state of the index per entity type: totals, embedding coverage (embedded / total), and last ingested timestamps. Check this before querying to understand what's actually in the store.
query
architecture.get_architecture
High-level summary of ingested memory: decision and constraint counts, active decisions, detected symbol communities with governing ADRs, warnings, and temporal context.
query
architecture.explain_answer
Re-runs the query pipeline and returns per-step provenance: keyword terms and LIKE hits, cosine scores per decision, BFS hops and neighbor IDs, and final RRF scores. Use this to understand why a result ranked where it did.
query
architecture.get_graph_schema
Returns the concrete SQLite-backed graph schema, table roles, column definitions, and optional row counts.
query
architecture.impact_of
Graph traversal from an ADR across typed edges (applies_to, depends_on, conflicts_with) up to max_depth hops. Returns affected files, symbols, and decisions with hop depth and edge confidence. Cycle detection included. Respects valid_at filtering.
analysis
architecture.diff_architecture
Shows what changed in architectural memory between two points: decisions and constraints added or removed, ADRs that appeared or closed. Accepts ISO-8601 strings or git refs — refs are resolved to commit timestamps via git2.
analysis
architecture.find_stale_decisions
Detects accepted decisions that may no longer match implementation reality. Four heuristic signals: deleted files (0.85), missing symbols (0.70), no recent commit activity (0.45), aged ADRs not yet superseded (0.35). Results sorted by confidence.
analysis
architecture.find_orphaned_code
Finds files and symbols with zero governing decisions — code that exists outside the known architectural record. Accepts an optional path prefix filter. Requires ingest_symbols to have been run first.
analysis
architecture.inspect_change_against_decisions
Takes a changed file set and surfaces constraint violations before you merge. Loads all active constraints for the repo — not just those with explicit file links. Confidence: high (accepted ADR), medium (proposed), low (short constraint text).
analysis
architecture.trace_symbol_history
Full architectural timeline for a named symbol: when it appeared, which decisions governed it at each point, and which commits and episodes touched those decisions. Events sorted oldest to newest.
analysis
architecture.trace_call_path
BFS over the symbol call graph (CALLS/IMPORTS edges) in outbound, inbound, or both directions. Supports exact and suffix name matching. Returns the call chain with a truncation flag if max_depth was reached. Respects valid_at filtering.
analysis
architecture.adr_lineage
Traverses the ADR supersession graph. Returns the full ancestor and descendant chain and the live accepted authority at the end. Cycle detection included. Uses the existing supersession_edges table — no schema changes required.
analysis
architecture.propose_links
Suggests candidate links (decisions, commits, symbols, routes) for an ADR via keyword + embedding similarity. All candidates carry explicit confidence scores. Nothing is auto-promoted — review before accepting.
analysis
architecture.validate_adr
Reads and validates an ADR file without writing to the database. Checks for missing title, decision text, or status; detects unknown status values, duplicate ADR IDs, and invalid supersession references. Returns errors and warnings separately.
analysis
architecture.generate_adr_draft
Produces an ADR markdown draft with the next sequential ID auto-assigned. Finds related existing decisions via keyword search on the title. Does not write files — returns the markdown and any warnings.
write
architecture.generate_adr_patch
Produces a git-ready unified diff for a new or updated ADR. Validates the target path stays inside the repository root. Does not write files or apply the patch.
write
architecture.retract
Soft-deletes a hallucinated or incorrect LLM-extracted fact. Cascades from decision to its active constraints. Optionally records a correction episode as an audit note. Idempotent — retracting an already-retracted entity adds a warning but does not error.
write
Config: Embeddings & LLM

All tools work without embeddings — architecture.query degrades gracefully to keyword search. Add a provider to unlock semantic search and LLM-powered episode extraction. Check architecture.index_status to see embedding coverage before querying.

Recommended · summarization & synthesis
prism-ml/Bonsai-1.7B-gguf
Small, fast, runs locally via Ollama or LM Studio. Used for structured fact extraction in record_decision_episode.
Recommended · embedding
microsoft/harrier-oss-v1-270m
Lightweight embedding model. Powers semantic search in architecture.query and ingest-time vector storage across all entity types.

ollama · openai · mock

Known gaps

Tracked explicitly so the current implementation doesn't imply support it doesn't have.

Tracked implementation gaps
Entity resolution for episode-sourced decisions is partial. The entity_nodes table exists and is populated, but record_decision_episode does not yet deduplicate semantically similar decisions across episodes.
temporal_edges are populated for ADR-typed edges (applies_to, depends_on, conflicts_with). Decision→Constraint and Commit→Decision edges are not yet emitted.
Module and service resolution in find_decisions_for_code returns a warning. File and symbol resolution work fully.
pull_requests table exists but is not populated by any tool. Git commit history is ingested; PR-level links are not.
evidence_spans are not yet populated by ADR sync or episode ingestion.
Cross-ADR conflict detection and consistency checking are planned for Phase 4.
Design principles
01
Bitemporal integrity
Historical facts are never overwritten. Supersession closes valid_to and creates a new record. Query as of any point in time.
02
Structured facts, before hallucinated context
Voids in the record are filled with tagged synthetic data. Every answer is traceable to a decision, commit, file, or symbol. Conflicts are surfaced, not suppressed.
03
Controlled writes
No freeform memory. No vague entities. No implicit acceptance of proposals. No invented links without confidence scores. The schema enforces what the rules require.
04
Canonical source hierarchy
When sources disagree: git wins for repo state, ADR markdown wins for accepted decisions. accepted > proposed. superseded ≠ current guidance.
